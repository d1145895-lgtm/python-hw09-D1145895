## 1. 程式用途與執行方式
這支程式用來整理桌遊體驗與電影欣賞兩場活動的報名資料。收到的原始文字包含多餘空白、大小寫不一致以及同一人重複報名的情況，程式先將字串格式統一並拆成串列，再轉換成集合去除重複名單、比較兩場活動的交集與差集，最後算出各場人數、總不重複人數、報名人次以及應收費用。

1. 點擊儲存庫中的筆記本檔案，或開啟 Google Colab 選擇從 GitHub 載入本儲存庫的筆記本。
2. 點選上方選單的執行階段並選擇全部執行，即可依序跑完三組測試並看到下方的輸出摘要。

## 3. 問題回答

### 問題一
測試一中，整理後的桌遊串列有 4 筆資料，為什麼桌遊費用應以 3 人計算？直接把字串拆成 list，和再轉成 set，各自保留了什麼、失去了什麼？

桌遊名單在轉小寫和去掉空白之後，串列裡有 amy、ben、amy、cora 共 4 筆資料，其中 amy 重複出現了兩次。依照活動規則，同一個人在同一場活動重複報名只算一位參加者，也只收一次費用，所以實際收費人數是 3 人，桌遊費用為 3 乘以 120 等於 360 元。

直接把字串拆成 list 時，會保留大家報名的先後順序，以及重複報名的紀錄，可以看出誰多填了一次；但這樣沒辦法直接算出實際要去重收費的人數，也沒辦法直接比對兩場名單。進一步轉成 set 之後，集合會自動把重複的人名刪掉，只留下不重複的參加者名單，而且可以直接做交集、聯集和差集運算；不過轉成集合的同時，原本的報名順序以及重複出現的次數就會不見。

### 問題二
測試三中，兩場活動只有 3 位不同的人，為什麼是 6 人次、總應收仍是 600 元？請用集合關係與算式說明。

在測試三中，電影名單整理並去重後的集合包含 amy、ben、cora 三個人，和桌遊集合的元素完全一樣。從集合關係來看，這兩個集合的交集和聯集都是這三個人，兩個方向的差集也都是空集合，代表這 3 位參加者同時報名了兩場活動。

總不重複人數看的是聯集裡有幾個人，所以是 3 人；而報名人次看的是兩場活動各自去重後的參與人數總和，算式為 3 加 3 等於 6 人次。因為兩場活動是分開計費的，這 3 個人兩場都有參加，就必須各自繳交兩邊的費用，所以總應收金額為 3 乘以 120 加上 3 乘以 80，等於 360 加 240，合計 600 元。
